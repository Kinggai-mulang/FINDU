# FINDU

**面向 PPP、PPP-AR 与 RTK 的 Windows GNSS 实时 工作台**

产品准备 · 后处理解算 · 实时监控 · 结果对比，在同一个桌面程序里完成

</div>

FINDU 是一个把 GNSS 精密定位日常工作串起来的桌面程序。你可以拖入一份观测数据，让它自动检查并准备精密产品，生成配置后直接解算；也可以接入 NTRIP 数据流，同时运行多路实时 PPP / RTK 方案，并在同一张图上比较它们的表现。解算由独立的 IPSPOS 引擎完成，FINDU 负责配置、调度、监控和分析。

支持的解算类型包括：

PPP、PPP-AR、PPP-RTK、RTK

同步支持：北斗 B2b、Galileo HAS、日本 CLAS（PPP-RTK）等改正来源，以及 RTCM3 SSR 实时产品。

> 当前版本 **v0.8.1**。本仓库不包含 IPSPOS 解算算法源码，只包含 FINDU 本身与引擎的二进制、版本清单（见[仓库范围](#仓库范围与数据)）。

## 下载与运行

1. 打开 [最新发布页](https://github.com/Kinggai-mulang/FINDU/releases/latest)，下载 Windows x64 便携包。
2. 完整解压，双击 `FINDU.exe`。请整体保留 `engine`、`product-tools`、`product-runtime` 等目录，不要单独挪走 exe。

运行环境：Windows x64、Microsoft Edge WebView2 Runtime、Microsoft Visual C++ 2015–2022 x64 运行库。程序未做代码签名。产品下载和实时数据流需要网络；**不需要另装 Python、MATLAB 或 Docker**。

## 功能一览

FINDU 分为四个页面，对应一次完整工作的四个环节。

### 数据与下载：从观测数据到可运行的配置

- **自动识别观测数据**：支持 RINEX、RTCM3、Unicore 二进制，以及引擎能读取的混合观测流；判断依据是文件里真实可用的观测历元，而不是扩展名或文件名。
- **只在需要时才问你**：数据里没有完整日期时，才要求补充观测的 GPST 日期；不会用电脑当天的日期去猜。
- **精密产品自动准备**：按观测的实际时段查找本地文件和缓存，必要时下载轨道、钟差、广播星历、OSB、天线文件等，检查覆盖范围与配套关系，然后生成后处理配置（OPT）。
- **DCB 单独处理**：DCB 在独立队列里尽力获取，成功与否都不影响主产品；失败、离线或超时只会提示，可以单独重试。
- **队列可控**：每个任务可取消、重试、移除；取消后保留断点，不删除已下载的部分数据。

### 后处理：批量、并行、可追溯

- **最多 32 路并行**，每路是独立的解算进程，互不影响。
- 可以导入已有的 OPT 并在界面里编辑，也可以直接使用「数据与下载」生成的配置。
- 提供排队、进度、实时日志和运行记录；完成后一键查看结果，历史结果可重新载入。
- 覆盖最终产品 PPP-AR、实时 SSR 产品回放、Galileo HAS、北斗 B2b、CLAS L6 与 PPP-RTK、RTK 等场景。
- 每个结果记录所用引擎的版本标识，方便日后复核。

### 实时监控：多路方案同时看

- **最多同时运行 16 路**实时会话，一次可对比最多 6 路同站方案。
- 支持 PPP 动态 / 静态、RTK 动态 / 静态；模糊度固定可选关闭、单历元、连续、固定保持；NTRIP v1 / v2 均可使用。
- 三种运行方式：**实时解算**、**回放**、**仅录制原始流**（把观测流和各类产品流保存到会话目录）。
- 每秒刷新。看得到：定位结果与解状态、Ratio 与固定卫星数、各数据流的接收状态与产品时效、延迟与断连。
- 查看窗口可选 5 / 15 / 30 分钟或全部缓存；手动缩放后固定在所选时间窗，后台继续接收，随时「恢复实时跟随」。
- 切换页面不会中断会话，回来后统计和曲线继续。
- **NTRIP 源表**：在数据流配置里点「源表」，即可获取服务器的挂载点列表，按格式、国家、内容（观测 / 星历 / SSR 改正）筛选，按与大致位置的距离排序，并可连接 8 秒实测该挂载点真正发送的 RTCM 消息。选中后自动填入挂载点。
- **卫星详情**：天空图（北向上、顺时针方位）、各星座的频点统计、按卫星分组的载噪比图；可按星座、频点或单颗卫星筛选。状态不确定时显示「未知」，不会沿用上一历元的旧值。

### 分析对比：把结果看明白

- 直接把 Log=4 结果日志或会话目录拖入分析页即可载入，支持一次拖入多个；拖入状态日志、运行日志等非结果文件时会明确提示。
- 单个结果或多个结果叠加对比（最多 6 份），页面包括：**结果总览、位置、连续性、独立测速、后验残差、产品覆盖**，以及 PPP / RTK 各自的诊断页：
  - 观测与质控；
  - 模糊度与固定（Ratio、固定卫星、候选与发布状态等）；
  - 大气与状态耦合（对流层、电离层更新、跨状态相关）；
  - RTK 专属的共视与差分、基站与同步。
- 位置以 ENU 显示。没有独立参考坐标时，ENU 表示相对位置的变化，界面上会明确标注；可自选显示原点。
- 跨天曲线标注 UTC 日期，并显示完整的时间范围和覆盖日数。
- 图例只显示区分各方案的部分（如 `KIN` / `STA`），不会出现被截断的长文件名。
- 滚轮缩放纵轴，Shift + 滚轮或底部滑块调整时间，点击图例筛选曲线。
- **长结果也流畅**：两份 47 小时、1 Hz 的结果（共约 34 万历元）同时载入约 5 秒，载入过程中界面不会冻结。超过 6000 点的曲线仅在绘制时抽稀，并保留首尾点与最高最低点，尖峰和状态跳变不会丢失；统计、事件和导出始终使用全部历元，也可一键切换为显示全部历元。

## 规模与可靠性

| 项目 | 容量 |
|---|---|
| 同时运行的实时会话 | 16 路 |
| 一次对比的结果 / 方案 | 6 份 |
| 并行的后处理任务 | 32 路 |
| 实时曲线缓存 | 每路最多 3600 历元，且不抽稀 |

- 实时数据以增量方式传输：运行得再久，每秒的开销也和刚启动时相同。
- 凭据（NTRIP 账号密码）只用于连接，不写入日志、报告和历史记录。
- 原始观测数据只读，任何环节都不会改写它。

各版本的测量方法、硬件环境和回归范围见 [docs](docs/) 下的验证记录，例如 [v0.8.1 验证记录](docs/VALIDATION-0.8.1.md)。

## 仓库范围与数据

本仓库保存 FINDU 的前端、Rust 接入层、数据协议、测试、产品下载辅助脚本和独立运行资源。**不包含 IPSPOS 解算算法源码**，`engine` 目录只有二进制与版本、哈希清单。

用户的观测数据、产品缓存、连接凭据、运行结果、编译产物和测试中间文件都不纳入 Git。默认的运行数据保存在程序旁的 `runtime` 目录，请把便携包放在可写目录。实时运行副本可能含连接凭据，请妥善保管。
