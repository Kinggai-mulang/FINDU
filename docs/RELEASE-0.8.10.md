# FINDU 0.8.10

## 本地天线与 DCB

数据与下载的产品方案中新增明确的“天线与 DCB”区域，两种文件并列显示，不再把本地 ANTEX 藏在高级设置里。

- 天线模型：拖入或浏览 `.atx` ANTEX 文件，也可粘贴路径。
- DCB：使用 Bias-SINEX `.BIA/.BSX` 中的同频码间差 DSB；精密 OSB、轨道和钟差不能替代。
- 填写本地文件后显示“本地固定文件”，ANTEX 自动更新选项禁用；点击清空恢复自动选择。路径“已填写”不等于有效期已校验，准备产品时检查内容及适用性。
- 空路径时 DCB 按观测日期查找更新，ANTEX 按参考框架检查版本；离线只查找本地和缓存。缺失、无效、更新失败仍保留原有状态提示。
- 通用文件输入框直接写明文件用途，浏览对话框标题对应当前字段，避免选择 DCB 时仍显示“选择观测文件”。

## B2B 系统覆盖

B2B 转换入口说明北斗需要匹配的 B-CNAV1 星历，普通 D1/D2 RTCM 星历不能替代。转换后显示实际轨道与钟差系统；缺少北斗时给出明确警告，不能因为生成了 GPS 文件就当成完整 B2B 产品。SP3 的全零缺测位置不计为有效覆盖。

已整理修正版同期数据：`Data/TEST/PRODUCT_COMPARE/6_matched_2026-10-18_CNAV1`，优先使用此目录。B2B 从原来的共享 RTCM 星历改用自身接收机日志中的 CNAV1；原始改正、引擎未改变。结果包含北斗 19 星、GPS 19 星；GPS 因星历覆盖变化与旧集不同。旧第五组及历次结果保留用于复现。

## 相位偏差解释

当前 WUM 与 WHU/CHC 的 BDS-3 相位信号不具备完整的共同宽巷组合，实际北斗宽巷只比较了 C06–C14 中的 5/7 颗 BDS-2 卫星。原始 CHC SSR 的 MW 一致性标志为 0，不能以码相位组合差直接判定整数固定能力。

覆盖页补充共同相位信号、卫星数量和实际参与北斗宽巷比较的 PRN。说明文字明确 ±0.1 周是差异统计门限，不是固定成功率；单独相位 OSB 的大小不能证明整数能力，需要配套钟差及原始整数/连续性标志。

本轮未修改偏差公式、信号映射或 GNSS 引擎。独立 Python 重算与原生北斗宽巷结果的最大 RMS 差小于 4e-15 周；这验证了当前输入下的计算一致性，不证明产品正确或 PPP-AR 可固定。
