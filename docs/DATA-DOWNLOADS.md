# 0.6.1 更新：RTS 基础准备与队列清理

RTS 在轨道、钟差文件有效且与实际观测有共同卫星/时间覆盖时，生成可送入后处理的基础 OPT。NAV、OSB、ANTEX 下载失败或校验问题保留在逐文件状态、队列警示及生成配置注释中；不增加新的界面选项。

基础配置不等于完整配套检查通过：未合格 OSB 留空且关闭 AR，缺少匹配 ANTEX 留空且关闭天线改正；NAV 缺失也允许导出配置并明确提示可能无有效定位。没有基本轨道、钟差或日期完全不匹配时不生成配置。其他等级保留原严格检查，PRIDE 参考解仍要求完整模型配套。

下载准备队列提供单项移除与“清除已结束”，保留产品和缓存，通过本地移除标记避免重启恢复。正在运行的记录必须先取消，不能直接移除。清除全部终态记录包含当前列表之外的记录，避免超过 100 项后无法清除。PRIDE 同样支持清理，已通过检查的参考保留引用能力。

以下为 0.5.0 的原始设计与验收记录，RTS 的最终行为以上述更新为准。

# 数据与下载 · FINDYOU 0.5.0

## 边界与流程

页面 → Tauri 产品队列 → FINDYOU 内的独立产品服务 → 本地/缓存/下载源 → 配套校验 → 生成 OPT → 既有独立 IPSPOS 后处理进程 → 结果曲线。

产品服务参考 gnss-product-download skill，复用已有脚本的独立快照与 FAST 地址表、时间工具；未依赖用户原仓库运行，未嵌入或修改算法。工具上游文件 SHA-256 见 product-tools/provenance.json；FAST 许可位于 product-tools/ThirdParty/FAST/LICENSE，运行组件许可位于 product-runtime/LICENSE.txt。固定模板已清除个人路径。产品模板不能宣称适用于任意引擎版本；当前随附正式 BetaV0.500。

每次提交生成 UUID 目录，不覆盖输入。计划记录真实观测跨度、源表版本、文件哈希、所选方案；失败不生成可运行 OPT。重试核对观测哈希并复用原计划，输入变化需重新提交。取消停止本次子进程树，保留断点；恢复时重新验证缓存。中断任务不会在下次启动时自动联网。不同观测串行准备以避免共享缓存冲突，单任务有界并行 1–8 文件。

实际序列、产品配套、星座与信号覆盖、OSB 时间、轨道框架和 ANTEX 均参与校验。前后边界仍要求轨道 900 秒、钟差 30 秒，不以缩减检查换取“成功”。单个中心失败不会阻止导出其他已就绪中心。RTS 与 Rapid 独立，GFZ final 的 AR 缺项不会由别家 OSB 补齐。

## 状态与故障

排队 → 识别/下载/校验 → 就绪 / 不完整 / 失败 / 已取消。上次运行中断显示“上次中断”。文件状态区分认证、网络、未找到、损坏、离线缺项、缺本地天线。重试不修改方案；可回到上方创建其他方案。关闭换源仅使用首个发布主机，仍可复用已校验本地文件。关闭天线下载时，包括后续识别到 IGS14 框架的天线任务，也不会联网下载天线。

下载源的目录条目不等于目标日期已经发布。公网时效、认证和服务可用性依赖源端；界面不把握手成功或文件存在当作产品校验成功。Hatanaka 与 RINEX 4 本轮要求用户先转换。RINEX 2 未记录明确跟踪属性时 AR 校验可保守失败，应核实信号或明确选择浮点。

## 手动后处理

默认显示文件表单，新建配置使用独立模板；输入 O、NAV、SP3、CLK、BIA、ATX、参考文件及可选产品回放流。仍保留多 OPT 导入、完整算法参数、PMode、ARMode、输出开关。手动草稿在运行前写入 runtime/config/post-drafts；真实任务继续创建独立运行副本。仿实时为先解算、再按历元回放。

## 图表口径

ADOP 对数轴固定 0.0001–1 cycle，合法小值及日志舍入为零的值贴下限，负值和缺测留空；提示与导出保留原值。相位后验 RMS 从 m 乘 1000 显示为 mm，伪距仍为 m，两图共享时间窗。原始诊断与 CSV 保持 m，标准化残差不换算。
