# FINDU 0.8.7 验证记录

日期：2026-11-04。Windows x64。引擎沿用 0.8.6，未修改 GNSS 算法、原生会话启动代码、增量桥接或曲线计算。

## 旧版复现与定位

- 从 0.8.6 复制隔离测试实例，使用 TEST/RTIET 的五份 Alloy 配置。先删除账号并改连本机模拟服务，五路均成功建立独立进程和连接。
- 再用五份原始配置短时实测约 25 秒：WHU、HC、PLANET、HAS、B2B 均为 running，各读取 24 个历元，无启动错误或残留待启动行；测试后全部停止。
- 部分产品/辅助流曾出现 state=3，但进程与观测仍在运行；连接重试与“进程未启动”是不同状态。短时接收不证明所有产品长期稳定、PPP 收敛或精度合格。
- 原先用户唯一已运行的 WHU 记录为正常停止，已读取 88 个历元，无解析或会话错误；未发现其他路创建进程的持久记录，无法仅据此确定用户当时的操作或拒绝原因。
- 代码确认：配置准备请求在逐路异常处理之外；该请求失败会中断后续启动。创建进程前被拒绝只弹窗，待启动行没有失败状态；成功提交后提前移除待启动行，下一次轮询前可能消失；原生列表按随机 ID 排序。

- 浏览器真实 React 组件、模拟 IPC：第二路配置准备失败，第三路后端拒绝，第一/四/五路继续启动；错误在对应行保留。覆盖延迟总览时行不消失、随机原生顺序不影响方案顺序、行内重试、详情单路启动和停止一路不影响其他四路。无脚本错误和横向溢出。脚本 tests/realtime-start-ui.mjs。
- `pnpm verify`：TypeScript、ESLint、Prettier 通过，23 个测试文件 / 132 项 Vitest 全通过；Rust `cargo test --manifest-path src-tauri/Cargo.toml --bin findyou`：111 通过、4 忽略、0 失败。
- Windows release 构建通过；隔离实例使用五份原始配置运行约 30 秒，五个独立进程全部 running、各收到 29–30 个历元，无会话错误。单独停止并重启 HC 后，HC 获得新进程和 run id，收到 12 个历元；其余四路保持原进程，历元数继续增长至 44。方案顺序保持 WHU / HC / PLANET / HAS / B2B。
