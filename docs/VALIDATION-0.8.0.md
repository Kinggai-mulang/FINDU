# FINDU 0.8.0 本地验证记录

日期：2026-10-30。Windows x64，IPSPOS BetaV0.611，GNSS Log=4 / StatusLog=1。

本机数值一致性、处理耗时和 30 分钟稳定性验收通过。具体输入、测量方法和硬件边界如下。

本次未修改估计、选星、改正或模糊度算法。IPSPOS 的新增代码集中于模式 0 只读解码、固定容量卫星快照及其独立发布线程。卫星诊断改用进程环境变量，不再扩展 OPT 配置结构或通用线程接口；相较上一候选版，4 个既有文件恢复原样，最终仅改动 7 个既有文件并新增快照模块的 .c/.h。源码基线提交为 `611e6c786200`；具体修改后源码哈希、两个程序哈希和接口能力版本见随包 `engine/manifest.json`。

## 实时差异根因与复测方法

旧回放脚本本身不保证等价输入。未修改的 BetaV0.611 用同一旧脚本也出现 4 种 RTK 结果哈希，PPP 为 591/592 行且有两种哈希（`baseline-timing-repro/summary.json`）。旧状态日志明确记录 PRODUCT 一开始接收 767 帧、队列仅容纳 512 帧、丢弃 255 帧；原因是脚本把导航前缀也发送给产品流。各连接还各自按墙钟发送，晚连接会追帧，超过 3 历元观测队列，基站同历元也不保证先到达。

修复仅在回放测试：等待全部连接就绪，导航只发给观测流；先发送并确认 BASE/PRODUCT 的累计接收帧，再发送 ROVE；每路完整 Log=4 结果提交后才进入下一历元。每步检查队列零丢帧，并比较同模式的完整结果行。没有更改 IPSPOS 的匹配容差、等待策略、队列大小或算法。

- 16 路短测（8 RTK + 8 PPP）各 120 历元，原始引擎、候选引擎未订阅、候选引擎订阅的结果逐行一致，零产品丢帧。证据：`barrier-smoke-1/summary.json`。
- 最终客户端连续运行 1,805.6 秒（超过 30 分钟），16 路各 1,805 历元，完整结果行与同模式原始基线全部一致，产品队列零丢帧；所有客户端正常完成停止。第 902.5 秒切换详情，第 1,685–1,705 秒模拟临时快照文件不可写后恢复，第 1,745 秒解除订阅，宽限后直到退出没有新发布。采集 P95 为 0.0011 ms、最大快照 8,529 字节；16 路私有内存相比启动稳定后样本最大增长 104 KiB，没有随历元线性增长。证据：`barrier-final-30min/summary.json`、`samples.json`、`resources.json`。

RTK 实时协议回放使用同一 ALLOY 观测作为两站，是零基线时序对照；非零基线数值回归由 T10/T11 的真实两站资料覆盖，不把零基线试验解释为外场精度证明。

## 性能测量

旧测量把不同 CPU 核心上的会话互相比较，且部分输入时序、历元数不同。测试机是 24 逻辑核心的 Intel Core Ultra 9 285K；跨核心比较以及包含网络等待的主线程总周期数，不能直接归因于诊断。旧超标记录保留在 `timed-solver-check`、`timed-solver-low-priority`，历史说明保留在 `previous-realtime-validation.md`，不删去失败证据。

最终测量使用隔离源码副本，在 `runOneGNSS` 与原样的 `CaptureSatelliteSnapshot` 调用两侧读取计时器。求解线程不逐历元写文件；结束后才写测量结果。正式 IPSPOS 工作树和发布程序均不含这些计时代码。性能按预定开关顺序比较相同输入、相同 CPU 核心、全部测量历元的平均总处理时间（求解 + 快照调用），不以较低的中位数替代平均值。

| 场景 | RTK 增幅 | PPP 增幅 | 数值 |
|---|---:|---:|---|
| 单会话，预热后 4 对重复完整回放 | +0.0533% | −0.0573% | 每次与未修改基线逐行一致 |
| 16 路真实实时，8 轮固定核心与同历元对照 | −4.478% | −0.352% | 全部 8 轮完整数据行一致 |
| 16 路持续处理，预热后 4 对完整回放 | +0.102% | −0.695% | 全部与原始基线逐行一致 |

表中多路数字针对唯一订阅会话，测试在 RTK 与 PPP 间切换，未同时订阅两路。16 路持续处理的整组总耗时变化：RTK -0.007%、PPP -0.525%，也均未超过 2%。实时对照每轮 80 个完整历元，分别比较 RTK 前 40 个和 PPP 后 40 个相同历元；证据为 `barrier-performance.json`、`barrier-performance-summary.json`。容量对照使用完整 T10/T14，证据为 `controlled-capacity/results.json`、`summary.json`。

单会话分别完整处理 T10 的 3,319 历元与 T14 的 21,931 历元，证据为 `controlled-diagnostics/results.json` 和 `summary.json`。负值视为测量波动，不解释为诊断使求解加速。2% 是本机同输入重复测量的验收目标，不是所有设备、网络和每一个孤立时间窗的零开销保证。

快照线程使用固定容量缓冲、非阻塞交接和原子替换，求解线程不执行诊断文件 I/O、不等待锁。默认关闭；FINDU 只给子进程注入环境变量，短期订阅解除后停止采集。前后端只保留最新完整快照，不累计逐星历史；Rust 读取上限 256 KiB。

## 卫星详情界面

天空图 500 px 高、PRN 放入标记内部并用高对比文字；北斗中国红、星座旗帜图例、较大计数、清晰柱边界与水平频点标签。载噪比按卫星分组、频点相邻，支持横向浏览；每次快照更新保留用户选择的显示窗口，改变筛选后重置。窄容器自动上下排列。

真实快照浏览器验证涵盖：默认不订阅、三图同快照、最多 1 Hz、筛选、天空图点选、隐藏停止轮询、收起销毁、缩放位置保留与窄屏无横向溢出。截图和测量位于 `runtime/satellite-ui`，最后一次完整界面检查通过，载噪比图更新 P95 为 1.2 ms；天空图实际画布 561×500 px，850 px 窗口上下排列且无横向溢出。PRN 与圆点／菱形使用同一完整标记，近邻遮挡时不会出现标签与其他星座底色错配。

## 边界

纯 UBX RAWX 解码、实时 CLAS 大气增强不在本轮扩展范围。`frames_without_output` 包括原生解码器等待 MSM 分片等情况，不能视为纯 CRC 错误计数。无当期可靠解算状态或角度时显示未知/缺失。UI 性能数据来自本机测试，并非所有硬件的保证。

复核入口：`tests/native-observation.py`、`tests/products-optional.py`、`tests/satellites-ui.mjs`、`tests/realtime-replay.py`，以及仓库现有 Rust/Vitest 测试。完整运行证据保存在本机 `runtime/validation-0611`，未随便携包携带观测原件。

尚未全面覆盖：所有真实设备上的断流重连、每一种磁盘故障、不同硬件的处理耗时对照、每条手动 UI 操作的桌面端自动化。已有单元测试、真实样例及浏览器图表验证不替代这些项目。
